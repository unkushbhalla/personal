① Indexing Pipeline

Usually offline
01

Source Data

PDFs, webpages, APIs, transcripts, databases, Notion pages, internal documents, etc.

02

Preprocess + Chunk

Clean the source and split it into smaller meaningful pieces that can later be retrieved independently.

03

Embedding

Each chunk is converted into a vector representing its semantic meaning.

04

Index / Vector Database

Store chunk text, embeddings and metadata so relevant chunks can be found efficiently later.

② Query Pipeline

At query time
05

User Query

The user asks a question. The system may clean, rewrite or expand the query before retrieval.

06

Hybrid Retrieval

Query embedding enables semantic search while keyword search can catch exact terms, names and identifiers.

07

Reranking

A reranker can examine retrieved candidates more carefully and put the most useful chunks first.

08

Prompt → LLM → Answer

Retrieved context is placed into a prompt alongside the user's question. The LLM generates the final response.

The mental model to remember

🧠 Embedding ≠ Retrieval An embedding is a numerical representation. Retrieval uses those representations to find relevant chunks.
📚 RAG ≠ Fine-tuning RAG gives the model external context at inference time. It doesn't permanently teach the model the retrieved information.
🎯 Retrieval is critical If the right information isn't retrieved, even a powerful LLM may produce an incorrect or incomplete answer.
🔎 Hybrid search Vector search captures meaning. Keyword search catches exact terms. Combining them can improve retrieval.
🏆 Reranking Retrieval may produce several candidates. A reranker can examine them more deeply and prioritize the strongest evidence.
💬 LLM's job The LLM receives the question plus retrieved context and uses that context to formulate the final response.
