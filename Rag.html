③ What Determines RAG Quality?

Six Factors

A RAG system is not good simply because it uses a powerful LLM. Multiple components influence the final result.

Think: "Can I get the right information, in the right form, to the right model, so it produces the right answer?"

01

Model Quality

How capable is the LLM at understanding context, reasoning over it and generating an accurate response?

02

Data Quality

Is the underlying knowledge accurate, current, complete, clean and trustworthy?

03

Search Type

Does vector, keyword, hybrid or metadata-filtered search find the information the user actually needs?

04

Prompt Type

Does the prompt clearly tell the LLM how to use the retrieved context and how to answer?

05

Chunking Strategy

Are documents divided into useful pieces, or has important context been separated?

06

Embedding Quality

Does the embedding model represent semantic meaning well enough for relevant chunks to be discovered?

④ How Do We Actually Evaluate RAG?

Evaluation Lab

Separate the problem into two questions:

Retrieval Quality: Did the system retrieve the right information?
Generation Quality: Did the LLM use that information correctly?

🔎 Retrieval Quality

Find
Measures whether the retrieval system found the relevant chunks.

✨ Generation Quality

Answer
Measures whether the LLM generated a useful, grounded and correct answer from the retrieved context.

The key distinction: Embeddings help represent meaning. Retrieval uses those representations to find information. Reranking improves the ordering of candidates. The prompt gives context to the LLM. Evaluation tells you whether the entire system actually worked.
